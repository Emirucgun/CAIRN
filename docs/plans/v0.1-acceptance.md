# v0.1 acceptance checklist

For ticking the boxes in SPEC §Roadmap → v0.1. Each box lists what proves it and how to check it yourself.

State on 2026-11-27: 266 tests in 29 files pass locally. CI runs the unit tests on Linux, macOS and Windows, and the perf benchmark gated on Linux (report-only on macOS and Windows); see the PR's checks for the latest run.

## Check everything at once

```bash
pnpm install
```

```bash
pnpm lint && pnpm typecheck && pnpm build && pnpm test
```

```bash
pnpm perf
```

Try it on a real repo of your own (after `pnpm build`). Replace the path with your CAIRN checkout:

```bash
cd ~/some/project && node ~/path/to/CAIRN/bin/cairn init
```

Then, in that project: `cairn doctor`, `cairn map`, `cairn read <file>#<symbol>`, and `cairn --agent me context` twice, with an edit in between (spelled with the same `node …/bin/cairn` prefix).

## 1. Repo scaffolded: pnpm, TS strict, ESM, vitest, eslint, `bin/cairn`, CI on GitHub Actions (Linux + macOS)

- **Code:** `package.json` (`"type": "module"`, `bin.cairn`), `tsconfig.json` (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), `eslint.config.js` (typescript-eslint strict), `vitest.config.ts`, `bin/cairn`, `.github/workflows/ci.yml`.
- **Tests:** `test/smoke.test.ts` (CLI prints its version).
- **CI:** the `test` job runs lint, typecheck, build and test on `ubuntu-latest`, `macos-latest` and `windows-latest` (actions: `checkout@v7`, `setup-node@v7`, `pnpm/action-setup@v6`).
- **Windows:** repo paths are canonicalized (git's `C:/…` and 8.3 short names vs Node's long `C:\…` names), renames retry while another process holds a file, `cairn read` never serves stray `\r` from CRLF blobs, and repo paths are always shown with `/`.
- **Check yourself:** `node bin/cairn --version` after `pnpm build`.
- **Note:** TypeScript is pinned to 6.0, because typescript-eslint doesn't support TypeScript 7 yet.

## 2. `src/git/` wrapper with typed helpers for rev-parse, ls-tree, diff-tree, notes, and the tmp-index snapshot

- **Code:**
  - `src/git/exec.ts`: the only place git is spawned.
  - `src/git/repo.ts`: rev-parse, HEAD, `check-ignore`.
  - `src/git/objects.ts`: ls-tree, diff-tree, cat-file batch reader, history.
  - `src/git/index-file.ts`: the scratch-index primitives.
  - `src/git/notes.ts`: `refs/notes/cairn`.
- **Tests:**
  - `test/git/exec.test.ts`: version check; inherited `GIT_DIR`/`GIT_INDEX_FILE` are ignored; a missing directory is reported as such.
  - `test/git/repo.test.ts`: subdirectories, no commits, detached HEAD.
  - `test/git/objects.test.ts`: NUL-safe ls-tree, diff-tree with and without renames.
  - `test/git/blob-reader.test.ts`
  - `test/git/history.test.ts`
  - `test/git/index-file.test.ts`: refuses the user's index, even through a symlink; denied files never reach `.git/objects`.
  - `test/git/notes.test.ts`: byte-exact JSON lines, append without blank lines.
- **Check yourself:** `grep -rn "execa\|spawn(" src` should show only `src/git/exec.ts`.

## 3. `cairn init`, `cairn doctor`

- **Code:** `src/core/init.ts`, `src/core/doctor.ts`, `src/cli/init.ts`, `src/cli/doctor.ts`.
- **Tests:**
  - `test/cli/init.test.ts` (8 tests): creates `.cairn/`, the config and the `.gitignore` entry; is idempotent; never overwrites the config; works from subfolders and with no commits; gives a clear error outside a repo.
  - `test/cli/doctor.test.ts` (8 tests): healthy after init; FAIL before init or with a bad config; warnings for corrupt cache entries, unreadable cursors and a non-gitignored `.cairn/`; `--fix`.
- **Check yourself:** run `cairn doctor` in a fresh repo (FAIL, pointing to `cairn init`), then `cairn init`, then `cairn doctor` again (all ok).

## 4. Skeletons for TypeScript/JavaScript, Python, Dart, Swift via web-tree-sitter, cached by blob hash

- **Code:**
  - `src/core/skeleton/`: one extractor per language (`typescript.ts`, `python.ts`, `dart.ts`, `swift.ts`) plus shared code in `common.ts`.
  - `index.ts`: per-file entries keyed by blob hash and generator.
  - `folder.ts`: per-folder entries keyed by tree hash (schema 2).
  - `pool.ts`: parse workers.
- **Tests:**
  - `test/grammars.test.ts`: all six grammars load on the pinned runtime.
  - `test/skeleton/typescript.test.ts`, `python.test.ts`, `dart.test.ts`, `swift.test.ts`: realistic files; kinds, export flags, signatures, line ranges including doc comments, imports.
  - `test/skeleton/build.test.ts`: cache hit without reading the blob; same content at two paths shares one entry; `.ts` and `.js` get separate entries; oversized, binary and secret-bearing files are skipped and never cached.
  - `test/skeleton/folder.test.ts`
  - `test/skeleton/pool.test.ts`
  - `test/core/cache.test.ts`: fixed reference keys; corrupt or wrong-schema entries are deleted and rebuilt; schema-1 migration; a randomized test that a lookup never returns an entry for a different hash.
- **Check yourself:** `cairn map --all` on your own code.
- **Note:** `map` now reads per-folder entries, while `read` and `context` use per-file entries. Both are keyed by git content hashes; see SPEC §Cache entry.

## 5. `cairn map`, `cairn read <path>#<symbol>`

- **Code:** `src/core/map.ts`, `src/core/read.ts`, `src/cli/map.ts`, `src/cli/read.ts`.
- **Tests:**
  - `test/cli/map.test.ts` (11 tests):
    - default depth 2, `--depth`, `--all`, `--max-symbols`, a single file, paths relative to the current folder
    - uncommitted changes reflected; denied files hidden; secret and binary files flagged
    - cache reuse, and the worker pool on a 320-file batch
  - `test/cli/read.test.ts` (13 tests):
    - one symbol with its doc comment, dotted members, a unique suffix
    - ambiguous name → exit 2 with the candidates; close-match suggestions for a missing name
    - whole file, `--no-line-numbers`, uncommitted edits
    - refuses `.env`, files containing a private key, and binaries
- **Check yourself:** `cairn map src --depth 3`, `cairn read src/<file>.ts#<function>`, and `cairn read <file>#<ambiguous-method>` (should exit 2).

## 6. `cairn context` with session cursors, working on uncommitted changes

- **Code:** `src/core/context.ts`, `src/core/sessions.ts`, `src/cli/context.ts`.
- **Tests:** `test/cli/context.test.ts` (15 tests):
  - a new agent gets the map; then "nothing changed"
  - uncommitted edits, additions and deletions shown as diffs
  - the commit list; the skeleton fallback over `max_diff_lines`
  - diffs withheld when either side contains a secret
  - a separate cursor per agent (`--agent` / `CAIRN_AGENT`); `default` with a hint; unsafe ids rejected
  - `--no-advance`
  - **the cursor is not advanced if the output fails**
  - an unreadable cursor, a pruned snapshot, a rewritten HEAD
  - the cap on detailed changes; a repo with no commits
- **Check yourself:** `cairn --agent me context`, then edit a file without committing, then `cairn --agent me context` again. You should see only that diff.

## 7. Safety test passes: user's index, HEAD and refs untouched

- **How it's enforced:**
  - Every `cairn` command run in the tests goes through `test/helpers/cli.ts`, which records the protected state before each call and fails the test if it changed. That covers all 55 command tests: 56 direct call sites, plus more runs through helper functions and loops.
  - The protected state is: the bytes of `.git/index`, `HEAD`, `packed-refs`, and every ref except `refs/notes/cairn`.
  - The snapshot tests (`test/core/snapshot.test.ts`) and the git-level tests (`index-file`, `notes`) check the same state directly.
- **The check itself is tested:** `test/helpers/safety-check.test.ts` proves it detects a change to the index, HEAD, a branch ref and packed refs, and that it ignores `refs/notes/cairn`.
- **Hard cases covered:** something staged by you survives a snapshot; snapshots work while your index is locked; a ten-step sequence of edits, commits, deletions, `reset --hard` and `stash`, where each snapshot must equal the tree git itself would write.
- **Check yourself:** in a repo with something staged, compare `git status`, `git stash list` and `md5sum .git/index` before and after running any cairn command.

## 8. `cairn map` on a 10,000-file repo: under 5 s cold, under 1 s warm

- **How it's measured:** `scripts/perf.ts` (`pnpm perf`) builds 10,000 files: 9,000 TS/Python/Dart/Swift files of 60–120 lines and 1,000 Markdown files. It times the built CLI as its own process with `map --depth 99`, which parses every file.
- **Results:**

  | Run | CI Linux (gate) | CI macOS (report-only) | 4-core dev box | Target |
  | --- | --- | --- | --- | --- |
  | cold | **3.7 s** | 12.0 s | 3.1 s | < 5 s |
  | warm | **0.56 s** | 1.39 s | 0.55 s | < 1 s |
  | after one edit | **0.60 s** | 1.49 s | 0.58 s | < 1 s |

- **Decision on record (2026-11-27):** CI enforces the targets on Linux only. macOS reports its numbers without failing, because the runner is about 8× slower at small-file I/O: building the fixture takes 14.4 s there against 1.4 s on Linux. Even a default-depth run, which reads almost nothing from the cache, takes 0.84 s on that runner.
- **Not yet measured:** a real Mac or a real Windows PC. CI's Windows perf job reports numbers but doesn't gate; `pnpm perf` on your own machine is the honest check.
- **What it took:** see `docs/plans/v0.1.md` §10. The changes were Liftoff-only WebAssembly (the Swift grammar exit stall), parse workers, synchronous cache I/O, folder skeleton entries, and compact `--json`.

## Gaps against the v0.1 plan

None of these block a box, but you should know about them before ticking:

- **Test fixtures:** plan §5 named shared fixture scripts in `test/fixtures/` (TS app, Python package, Dart app, Swift package, 2,000-file monorepo). Instead, each test builds its own small repo with `test/helpers/repo.ts`, and the large repo is the 10,000-file perf fixture. The per-language tests use realistic single files rather than whole sample projects.
- **Records:** algorithm 3 step 6 (records in `context`) is a no-op until v0.3.
- **pnpm/action-setup:** its README points to a successor action (`pnpm/setup`); v6 works today.
- **Summarizer settings:** `config.toml` now defaults to `provider = "off"` and accepts the BYOK settings (SPEC §Summarizer: bring your own key), but no provider is implemented until v0.2.
