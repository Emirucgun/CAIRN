### Manual smoke test with your own key (optional, costs a few cents)

Do this in a small project of your own, after `pnpm build`. Replace the path with your CAIRN checkout.

1. Run init:

   ```bash
   node ~/path/to/CAIRN/bin/cairn init
   ```

2. Set `[summarizer] provider = "anthropic"` and `model = "claude-haiku-5-5"` in `.cairn/config.toml`.
3. Export `ANTHROPIC_API_KEY` in your shell. Never put it in the config file.
4. Run `cairn doctor`. It should report the key as set, without printing it, and consent as not asked yet.
5. Run `cairn summarize src --dry-run`. You should see the plan and estimate, with no questions and no calls.
6. Run `cairn summarize src`. It asks for consent once, then confirmation.
7. Run `cairn map src`, then `cairn stats`.

On Windows PowerShell, set the key with `$env:ANTHROPIC_API_KEY = "…"`.

## 1. Summarizer interface: Anthropic, OpenAI-compatible (base URL), optional Ollama, fake provider; keys only from env

**Code**
- `src/summarizers/types.ts`: the interface, error kinds and `generatorId`.
- `anthropic.ts`: the official SDK, effort `low` where the model takes it, `max_tokens` 2048.
- `openai-compatible.ts`: `fetch` with retries, refusal and truncation handling.
- `fake.ts`: the fake provider.
- `index.ts`: `createSummarizer`.
  - Keys come only from env vars: `ANTHROPIC_API_KEY` (or the SDK's `ANTHROPIC_AUTH_TOKEN`), and `api_key_env` for others.
  - For Ollama, `/v1` is appended to the base URL.

**Tests**
- `test/summarizers/anthropic.test.ts`: the SDK against a mock server.
  - Request shape, and actual `usage`.
  - Effort only where the model supports it.
  - 429 retries.
  - Refusal, truncation and HTTP error mapping.
- `test/summarizers/openai-compatible.test.ts`:
  - Chat completions.
  - Retries using `retry-after`; giving up with the right kind.
  - Unreachable server.
  - No `Authorization` header without a key.
  - Refusal and truncation.
- `createSummarizer` cases:
  - Off by default.
  - The key is read only from the named env var.
  - Missing key fails with the env var's name.
  - A local server needs no key.
  - The Ollama `/v1` rule.
- `test/summarizers/fake.test.ts`.
- `test/cli/summarize.test.ts` → "names the env var when the key is missing, and never reads a key from config".

**Check yourself:** with `provider = "anthropic"` and no key exported, `cairn summarize` and `cairn doctor` should name `ANTHROPIC_API_KEY`.

- `test/cli/map-summaries.test.ts`:

**Check yourself:** run `cairn map`, `cairn read <file>` and `cairn context`, then `cairn stats`.

## Gaps against the v0.2 plan

None of these block a box, but you should know about them before ticking:

- **No real-API run.** Nothing has been sent to a real provider. The manual smoke test above is the only check against the real Anthropic API.
- **Proxies.** The OpenAI-compatible and Ollama providers use Node's `fetch`, which ignores `HTTPS_PROXY`. This is documented, not fixed (plan §5).
- **Estimates.** Input tokens are estimated as `chars / 4` × the model factor, and output as 150 tokens per call plus a thinking allowance. Actual spend from `usage` is reported after the run and recorded in `stats.jsonl`.
- **Price table.** The table is dated 2026-11-03 and covers current Anthropic models only. Other providers show "cost unknown" unless `price_*` is set.
- **Squash and rebase merges** still orphan git notes. This is the open question for v0.3 and doesn't affect summaries.
