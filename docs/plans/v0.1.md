## 4. Key design choices

**Snapshot (SPEC §Algorithm 1)**
- Use `GIT_INDEX_FILE=.cairn/tmp-index`: `read-tree HEAD` (or `--empty`), then `add -A`, then remove `.cairnignore` matches with `update-index --force-remove --stdin`, then `write-tree`.
- Built-in denies (`.env*`, `*.pem`, `*.key`, `*.p12`, `secrets.*`, and the SSH key files `id_rsa`, `id_dsa`, `id_ecdsa`, `id_ed25519` with `.pub` and `-cert.pub` variants) and `.cairn/` are passed to `git add -A` as `:(exclude,glob)` pathspecs. That way secret files are never even hashed into `.git/objects`; filtering after `add` would leave loose blobs behind.
- Denied and ignored paths are absent from the snapshot tree, so they never appear in `map`, `context` diffs or skeletons.
- Tracked files that match a deny rule are also removed from the tmp index. This keeps the rule "never index" true even for committed `.env` files.
- Files over 1 MB and binary files stay in the tree, so the map stays truthful, but they get no skeleton. Binaries are detected with a NUL byte in the first 8 KB. Any file containing a private key header gets no skeleton either, whatever its name (`src/core/secrets.ts`).
- A lockfile (`.cairn/snapshot.lock`, O_EXCL with a stale-PID check) stops a CLI run and a later MCP server from racing on the same tmp index. It can't be `tmp-index.lock`: git itself creates `<index>.lock` while writing that index.

**Skeletons (SPEC §Algorithm 2, steps 1, 2 and 6)**
- One tree-sitter query file per language captures: functions, classes, methods (nested as `Class.method`), interfaces, type aliases, enums, top-level consts, and imports. Dart adds mixins and extensions; Swift adds structs, protocols and extensions.
- `sig` is the declaration text up to the body, with whitespace collapsed and a cap of 200 characters. `lines` uses 1-based inclusive line numbers.
- Extension to language: `.ts .mts .cts → typescript`, `.tsx → tsx`, `.js .mjs .cjs .jsx → javascript`, `.py → python`, `.dart → dart`, `.swift → swift`.
- Cold builds parse in one process with grammars loaded once. Cache writes go to a temp file and are then renamed, so they are atomic.
- A skeleton entry uses `layer: "skeleton"`, `summary: null` and `children: null`.

**map**
- Walks the snapshot tree with `ls-tree -r -t`. For each folder it lists child folders, then files with their exported symbol names.
- `--depth n` counts expanded folder levels with the start folder as 1, default 2: the start folder and its subfolders are expanded, deeper folders are collapsed to file and token counts. Only files in expanded folders are parsed. Text output is an indented tree; `--json` emits structured output.
- Files list exported symbols by default (`--all` for every symbol), capped at 40 per file (`--max-symbols`). Token figures are `bytes / 4` estimates.

**read `<path>[#symbol]`**
- Hashes the working file with `git hash-object` and fetches or builds its skeleton.
- Matches `symbol` exactly first, then as a dotted path (`Class.method`). If the name is ambiguous it lists the candidates and exits 2.
- Prints the lines with line numbers. With no `#symbol` it prints the whole file.

**context (SPEC §Algorithm 3, v0.1 subset)**
- Steps 1–5 and 7 as specified. Step 6 (records) is a no-op until v0.3.
- "Folders the agent touched recently" means the parent folders of the paths changed since the cursor.
- The cursor is written only after stdout has flushed successfully.
- Agent id comes from `--agent`, then `CAIRN_AGENT`, then a fallback (see Q4).
- Additions: commits since the agent's last HEAD are listed (max 20; skipped with a note if that HEAD no longer exists). At most 40 files get a diff or skeleton, up to 200 more are listed by name. A diff is withheld if either side of the file contains a private key. If the last snapshot tree was pruned by `git gc`, or the cursor is unreadable, the agent gets a fresh repo map. `--no-advance` shows context without moving the cursor.

**init**
- Creates `.cairn/` and the default `config.toml` (the SPEC §Config values).
- Appends `.cairn/` to `.gitignore` only if it is missing. Running it twice has no further effect.

**doctor**
- Checks that this is a git repo, git is 2.38 or newer, `.cairn/` exists, the config parses, and every grammar loads.
- Scans the cache: it parses each entry with zod, recomputes the key from its fields and checks the file path. It reports corrupt entries and deletes them only with `--fix`.
- Exits non-zero when a check fails.

**Output:** every command supports `--json`. Errors use one-line messages with the fix (SPEC §Failure modes).

## 5. Tests

- **Fixtures** (`test/fixtures/*.ts`): scripts that build temp repos for a TS app, a Python package, a Dart app, a Swift package, a 2,000-file monorepo, an empty repo with no commits, and a repo with a detached HEAD.
- **Unit tests:** the cache key (golden vectors), the zod schemas (a higher `schema` is rejected), ignore rules, and skeleton extraction per language against golden JSON.
- **Snapshot tests:** uncommitted, untracked and deleted files are reflected; `.cairnignore` and denies are excluded; the no-commit repo works.
- **Command tests:** `init`, `doctor`, `map`, `read` and `context`. For context, the first run returns a map; after an edit, the next run shows only that diff; a large diff falls back to the skeleton; the cursor advances only on success.
- **Safety test** (acceptance box 7): after every command, `.git/index`, `HEAD`, `packed-refs` and all of `for-each-ref` except `refs/notes/cairn` are byte-identical. This runs as an `afterEach` hook on every command test.
- **Property test:** random edits followed by a lookup never return an entry whose `object.hash` differs from the current blob.
- **Performance** (acceptance box 8): `pnpm perf` generates 10,000 files and times `map` cold and warm against the 5 s and 1 s targets. It runs in CI as a separate job so a slow run doesn't make unit tests flaky, but the job still fails when a target is missed.

## 7. Risks

- **Grammar/runtime ABI.** `tree-sitter-wasms` was last published in Oct 2025, and the latest `web-tree-sitter` (0.27) may not load its grammars. The fallback is to pin an older `web-tree-sitter` or build the six grammars to WASM ourselves and vendor them. The step-1 spike settles this early.
- **Warm `map` under 1 s on 10k files.** That means a snapshot (about 300 ms) plus `ls-tree` plus 10k cache reads. If reading 10k JSON files is too slow, the fix is an aggregate cache per tree hash, which is a data-model change. I'd raise it as a spec update first.
- **Cold `map` under 5 s.** That means parsing about 10k files in WASM. If needed, extraction can move into worker threads. That adds no dependency.

## 8. Questions before I start

These are also added to SPEC §Open questions.

- **Q1 — `imports` in a cache entry.** The cache is keyed by blob hash, so the same content at two paths shares one entry. A resolved import like `src/lib/supabase.ts` depends on the file's path, though. **Proposal:** store raw specifiers in the cache (`"../lib/supabase"`) and resolve them to repo paths when a command reads the entry.
- **Q2 — skeleton `generator_id`.** The spec says `ts:<grammar-version>`. Changes to the extraction queries must also invalidate the cache, and the same bytes in a `.ts` file and a `.js` file parse differently. **Proposal:** use `ts:<lang>@<grammar-pkg-version>+x<extractor-version>`, for example `ts:typescript@0.1.13+x1`.
- **Q3 — token counting cost.** Running `js-tiktoken` over every source file on a cold 10k-file `map` would blow the 5 s budget. **Proposal:** use a fast `chars / 4` estimate for `tokens.source` in cache entries, and exact tiktoken counts only for text CAIRN actually serves. Savings figures would then be "served (exact) vs. full read (estimated)", and labelled that way.
- **Q4 — default agent id.** What should be used when none of `--agent`, `CAIRN_AGENT` or an adapter is present? **Proposal:** `default`, plus a one-line hint in the output.

## 10. Performance findings (step 10)

`pnpm perf` builds a 10,000-file repo (9,000 TS/Python/Dart/Swift files of 60–120 lines, 1,000 Markdown) and times the built CLI as a separate process. The gate is `map --depth 99`, which parses every file.

| Run | First attempt | Now (4-core Linux) | Target |
| --- | --- | --- | --- |
| cold | 22.4 s | ~3.1 s | < 5 s |
| warm | 1.5 s | ~0.55 s | < 1 s |
| warm, after one edit | 1.7 s | ~0.58 s | < 1 s |

CI gates the targets on Linux; macOS runs report-only (decided 2026-11-27), because its runner is ~8x slower at small-file I/O. Before folder skeletons, CI measured Linux 5.6 s cold / 1.0 s warm and macOS 12.8 s / 2.0 s.

What it took, in order of impact:

1. **Swift grammar exit stall (~13 s).** After any Swift parse, V8 tiered the 3 MB Swift grammar up to TurboFan in the background, and the process (and `Worker.terminate()`) waited for it before exiting. Fix: `--liftoff-only`, set via `v8.setFlagsFromString` in `src/v8-flags.ts`, imported first by the CLI. Liftoff parses ~1.6x slower.
2. **Parse worker pool** (`src/core/skeleton/pool.ts`): 4 workers that parse, build and write cache entries. Used for batches of 300+ files, started after 32 cache misses so an edit or two parses inline.
3. **Synchronous cache I/O**: 9,000 small reads took 45 ms with `readFileSync` vs 732 ms with `fs/promises` (thread-pool hop per call).
4. **Compact `--json` unless stdout is a TTY**: pretty-printing a 10k-file map cost ~200 ms.
5. **Skip the dynamic-import walk** unless the source mentions `require` or `import(`: ~17% of TypeScript extraction time.
6. `git cat-file --batch` now uses `child_process` directly; with execa, awaiting it could settle before the child exited.
7. **Folder skeletons** (cache schema 2, SPEC §Cache entry): one entry per folder with its direct files' skeletons, keyed by tree hash. A 10k-file map reads ~350 entries instead of 9,000 and a cold run writes ~350 instead of 9,000. An edit re-parses the files of the edited folder and its ancestors (29 in the fixture).
